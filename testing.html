Testing guide

Everything needed to verify the project: an automated test suite that runs right here in the browser, a checklist that walks through each requirement of the brief in the simulator, and the commands for running the tests and benchmark from a terminal.

1. Run the automated tests

19 tests check that the algorithms are correct, not just that they run: A* is optimal, space-time paths never cross an active laser, every lock has exactly one solution, the fuzzy rules behave sensibly, and the agent clearly beats a fixed plan. They take a few seconds. The same tests run from the command line with npm test.

3. Measure performance

The brief asks for evaluation using completion time, path cost, states explored and success rate. Open the Benchmark page and press Run experiment with the defaults (30 Dynamic facilities). Expect the full UNIT-7 agent to escape about 100% of the time and the fixed script about a third of the time. The page also shows reference results from 100 facilities for comparison.

4. Run it from a terminal

You need Node.js 18 or later. There are no packages to install.

# get the code
git clone https://github.com/RohanRaoCs/ai-escape-room.git
cd ai-escape-room

# 19 correctness tests (the same ones as above)
npm test

# full evaluation on 100 facilities, about 1 minute; writes results/summary.md and CSVs
npm run bench

# serve the site locally at http://localhost:3000 (or just open index.html)
npm start

5. Deploy your own copy

The site is plain HTML, CSS and JavaScript with no build step, so it can be hosted anywhere.

Vercel

Fork the repository on GitHub, then in Vercel choose Add New → Project, import the fork and press Deploy. No settings need changing; vercel.json is already included. From a terminal, npx vercel does the same.

GitHub Pages

In the repository, go to Settings → Pages, choose "Deploy from a branch", select main and / (root), and save. The site appears at <user>.github.io/ai-escape-room.
